# Лабораторная 2 — тестирование PizzaTime

Тесты находятся в `lab2/tests/` и запускаются штатным runner Django. Есть тесты форм, интеграции HTTP-представлений с тестовой БД и сессиями, а также сценарии корзина → оформление → успешный результат. Тесты независимы: данные создаются внутри теста или в `setUpTestData`, БД изолируется Django.

## Запуск

```bash
python manage.py test lab2
```

Покрытие с исключением миграций, конфигурации и тестового кода:

```bash
python -m pip install coverage
coverage run --source=main --omit='*/migrations/*,*/tests.py,*/tests/*,*/apps.py,*/admin.py,*/context_processors.py' manage.py test lab2
coverage report -m
```

Требуемый порог: не менее 70%. HTTP-подмены внешних систем не требуются: платёжных и иных HTTP-интеграций в приложении нет. Для изолированной проверки хеширования пароля в тесте формы используется `unittest.mock`; тесты внешнего HTTP-клиента следует добавить при появлении реального внешнего сервиса.

## Arrange–Act–Assert и покрытие требований

Тестовые данные (Arrange) создаются в setup/помощниках, действие (Act) выполняется вызовом формы или Django test client, результат (Assert) проверяется явными утверждениями. Параметризация граничных значений сделана циклами с `subTest`.

| Группа | Проверяемое поведение |
|---|---|
| `test_forms.py` | Выбор доставки/самовывоза, адрес, согласие, email и выбор оплаты; длина отзыва и диапазон рейтинга; телефон, возраст и хеширование пароля. |
| `test_storefront.py` | Фильтрация/сортировка, 404, последовательные переходы корзины, пустое оформление, промокод и скидка, ошибки формы, сохранение сессии, создание/редактирование/удаление отзывов и права доступа. |
| `test_storefront.py` | Интеграция страниц с моделями БД, административная статистика и доступ к ней. |

## Результат выполнения

`python3 manage.py test lab2` — **25 тестов пройдены** в локальном окружении Python 3.9 / Django 4.2.

Покрытие проекта не подтверждено. `coverage.py` отсутствует, установить его не удалось из-за отсутствия сетевого доступа. Дополнительно проверен стандартный модуль `trace`, но его отчёт в данном запуске охватил тестовые модули и настройки, а не `main.views`/`main.forms`, поэтому этот процент нельзя считать покрытием приложения или подтверждением порога 70%. В целевой конфигурации (Dockerfile: Python 3.12, requirements: Django 6) выполните команды выше и проверьте `coverage report -m`; порог 70% остаётся непроверенным до доступности coverage.py.
