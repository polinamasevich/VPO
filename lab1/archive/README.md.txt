# Лабораторная 1 — описание и спецификация требований

## Описание проекта

**PizzaTime** — веб-сайт пиццерии для посетителей и клиентов: помогает ознакомиться с меню и компанией, собрать корзину и передать сведения для заказа доставки или самовывоза. Сотрудники управляют содержимым сайта через административную панель Django.

**Стек:** Python 3.12; Django (точная версия закреплена в `requirements.txt`); Django Templates, HTML/CSS; Django ORM; SQLite при локальном запуске и PostgreSQL при наличии `DATABASE_URL`. Matplotlib используется для графика статистики, WhiteNoise — для статических файлов.

**Архитектура:** браузер отправляет запросы маршрутизатору Django (`myproject/urls.py`, `main/urls.py`); представления `main/views.py` обрабатывают запросы, используют формы `main/forms.py`, модели `main/models.py`, сессию корзины и шаблоны из `main/templates/`. ORM обращается к SQLite или PostgreSQL. Изображения лежат в `media/`, стили и статические ресурсы — в `main/static/` и `static/`. Сотрудник управляет записями через Django Admin.

| Модуль | Ответственность |
|---|---|
| `myproject/` | Настройки Django, корневые URL, WSGI/ASGI. |
| `main/models.py` | Каталог, категории, промокоды, новости, отзывы, контакты, вакансии и сведения о компании. |
| `main/views.py` | Страницы, каталог, корзина, оформление, отзывы, статистика. |
| `main/forms.py` | Проверка данных регистрации, отзыва и оформления заказа. |
| `main/templates/`, `main/static/` | HTML-шаблоны, CSS и статические изображения интерфейса. |
| `main/migrations/` | Изменения схемы и начальные данные БД. |

**Точки интеграции:** реляционная БД; файловая система для `media/` и статики; сессии Django для корзины. Внешних сервисов оплаты/доставки и HTTP-интеграций нет. Платёжный выбор в форме не вызывает провайдера.

**Сборка и запуск** из корня репозитория:

```bash
python -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

Затем откройте `http://127.0.0.1:8000/`. Контейнерный запуск: `docker compose up --build`.

## Бизнес-требования

Сайт PizzaTime предоставляет клиенту каталог пиццы и информацию о пиццерии, позволяет собрать корзину и отправить данные для доставки/самовывоза. Это упрощает выбор ассортимента и передачу заказа сотрудникам. Цели: показать актуальные товары и сведения, рассчитать стоимость с промокодом, обеспечить оформление и обратную связь через отзывы.

## Пользовательские требования и сценарии

Акторы: **Посетитель** (в том числе незарегистрированный клиент), **Зарегистрированный клиент**, **Сотрудник/администратор**.

```mermaid
flowchart LR
  Guest[Посетитель] --> UC1((Просмотреть меню и карточку товара))
  Guest --> UC2((Добавить товар и изменить корзину))
  Guest --> UC3((Оформить доставку или самовывоз))
  Guest --> UC4((Просмотреть новости и сведения о компании))
  Guest --> UC5((Зарегистрироваться / войти))
  Guest --> UC6((Просмотреть отзывы))
  Client[Зарегистрированный клиент] --> UC7((Оставить / изменить / удалить свой отзыв))
  Staff[Сотрудник / администратор] --> UC8((Управлять данными через Django Admin))
  Staff --> UC9((Просмотреть статистику))
```

| ID | Пользовательское требование | Основной сценарий |
|---|---|---|
| ПТ-01 | Посетитель может найти товар в меню и посмотреть описание, цену и изображение. | Открыть меню → выбрать товар → просмотреть карточку. |
| ПТ-02 | Посетитель может собрать и скорректировать корзину. | Добавить товар → увеличить/уменьшить количество или удалить позицию. |
| ПТ-03 | Клиент может отправить данные заказа на доставку или самовывоз. | Заполнить форму → при доставке указать адрес → подтвердить согласие → отправить. |
| ПТ-04 | Клиент может применить действующий промокод к корзине. | Ввести код при оформлении → увидеть скидку и итог. |
| ПТ-05 | Посетитель может зарегистрироваться и войти в учётную запись. | Заполнить форму регистрации либо форму входа. |
| ПТ-06 | Посетитель может читать отзывы, а авторизованный пользователь — управлять собственными отзывами. | Открыть отзывы → создать/изменить/удалить отзыв. |
| ПТ-07 | Сотрудник может вести справочные данные через административную панель и видеть статистику. | Войти сотрудником → открыть Admin или страницу статистики. |

## Функциональные требования

| ID | Требование | Проверка / результат сверки |
|---|---|---|
| ФТ-01 | Главная страница отображает избранные товары, партнёров и последнюю новость. | GET `/`; ответ 200 и наличие контекста — реализовано. |
| ФТ-02 | Меню показывает товары и категории. | GET `/items/`; ответ 200 — реализовано. |
| ФТ-03 | Меню фильтруется по идентификатору категории. | GET `/items/?category=ID`; проверить набор товаров — реализовано. |
| ФТ-04 | Меню сортируется по цене по возрастанию/убыванию и по названию. | Проверить порядок queryset для `sort` — реализовано. |
| ФТ-05 | Карточка существующего товара показывает его данные. | GET `/items/<id>/`; ответ 200 — реализовано. |
| ФТ-06 | Запрос карточки отсутствующего товара возвращает 404. | GET несуществующего ID — реализовано через `get_object_or_404`. |
| ФТ-07 | Добавление товара в корзину доступно POST-запросом и увеличивает количество. | POST `/cart/add/<id>/`, затем проверить сессию — реализовано. |
| ФТ-08 | Корзина показывает доступные позиции, количество и сумму. | GET `/cart/` с наполненной сессией — реализовано. |
| ФТ-09 | В корзине можно увеличить, уменьшить или удалить позицию. | POST update с каждым допустимым action — реализовано. |
| ФТ-10 | Нельзя перейти к оформлению с пустой корзиной. | GET `/checkout/` с пустой сессией перенаправляет в корзину — реализовано. |
| ФТ-11 | Форма оформления проверяет имя, телефон, email, способ получения, оплату и согласие. | Наборы валидных/невалидных данных в `CheckoutForm` — реализовано. |
| ФТ-12 | Для доставки обязателен адрес; для самовывоза адрес не требуется. | Проверка формы на обоих значениях — реализовано. |
| ФТ-13 | Действующий промокод без учёта регистра уменьшает итог на заданный процент. | Оформление с активным кодом и проверка сумм — реализовано. |
| ФТ-14 | Неактивный или неизвестный промокод не применяется и отображает ошибку. | POST с некорректным кодом — реализовано. |
| ФТ-15 | После успешного оформления содержимое корзины очищается. | Проверить сессию после валидного POST — реализовано. |
| ФТ-16 | Клиент может зарегистрироваться; пароль сохраняется хешированным. | POST регистрации и `check_password` — реализовано. |
| ФТ-17 | Регистрация проверяет формат телефона и совершеннолетие пользователя. | Граничные значения формы — реализовано. |
| ФТ-18 | Авторизованный пользователь может создать отзыв с рейтингом 1–5 и текстом от 5 символов. | POST валидных/невалидных данных — реализовано. |
| ФТ-19 | Автор отзыва или сотрудник может изменить/удалить отзыв. | Проверить права владельца, другого пользователя и staff — реализовано. |
| ФТ-20 | Посетители могут читать новости, сведения о компании, контакты, промокоды, вакансии и условия. | GET соответствующих URL — реализовано. |
| ФТ-21 | Только staff имеет доступ к статистике; график строится по имеющимся товарам. | GET `/stats/` как гость/staff и наличие данных графика — реализовано. |
| ФТ-22 | Успешное оформление должно сохранять заказ и его позиции в БД для последующей обработки. | Проверка наличия модели и записи заказа — **не реализовано (ДЕФ-01)**. |
| ФТ-23 | Оплата картой должна подтверждаться платёжным провайдером. | Проверка интеграции/статуса платежа — **не реализовано (ДЕФ-02)**. |

## Диаграмма состояний оформления заказа

В текущем коде нет сохраняемой сущности `Order`. Поэтому диаграмма описывает доступные состояния процесса в рамках сессии. После успеха корзина очищена, а данные заказа показаны только на HTML-странице.

```mermaid
stateDiagram-v2
  [*] --> Корзина: добавить товар в сессию
  Корзина --> Корзина: изменить количество / удалить позицию
  Корзина --> Заполнение: открыть оформление [корзина не пуста]
  Корзина --> Корзина: открыть оформление [корзина пуста] / redirect
  Заполнение --> Заполнение: отправить форму [валидация не пройдена]
  Заполнение --> Заполнение: неизвестный или выключенный промокод
  Заполнение --> Подтверждён: POST [форма валидна и промокод валиден или пуст]
  Подтверждён --> Завершён: показать страницу успеха и очистить корзину
  Завершён --> [*]
```

Условия: для доставки требуется адрес; согласие обязательно; промокод, если указан, должен существовать и быть активным. Платёжное подтверждение в приложении не выполняется, отдельной сущности заказа и переходов «готовится/доставляется» нет.
