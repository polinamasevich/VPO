# Дефекты и расхождения требований с реализацией

## ДЕФ-01 — заказ не сохраняется после оформления

- **Серьёзность:** высокая для операционной обработки.
- **Шаги:** добавить товар в корзину, заполнить валидную форму оформления, отправить её.
- **Фактически:** показывается страница успеха, корзина очищается; модель заказа и записи в БД отсутствуют.
- **Ожидается:** заказ и состав сохраняются с идентификатором/данными клиента для обработки персоналом.
- **Связь:** ФТ-22; цель ПТ-03 достигается только как демонстрационная форма.

## ДЕФ-02 — метод «банковская карта» не проводит платёж

- **Серьёзность:** высокая для реального приёма заказов.
- **Шаги:** выбрать оплату картой и оформить заказ.
- **Фактически:** способ оплаты отображается в данных формы; обращения к платёжному провайдеру и статуса платежа нет.
- **Ожидается:** платёж авторизуется внешним провайдером, результат связан с заказом.
- **Связь:** ФТ-23.

## ДЕФ-03 — секретный ключ имеет небезопасное значение по умолчанию

- **Серьёзность:** высокая при публикации конфигурации без `DJANGO_SECRET_KEY`.
- **Шаги:** запустить приложение с отсутствующей переменной `DJANGO_SECRET_KEY`.
- **Фактически:** используется публичная строка `django-insecure-local-development-key-change-me`.
- **Ожидается:** для production запуск завершается ошибкой при отсутствии секретного ключа; значение для разработки не допускается в production.
- **Связь:** НФТ-07.

## ДЕФ-04 — тест оформления в исходном наборе не передаёт обязательное согласие

- **Серьёзность:** средняя (тест всегда получает невалидную форму).
- **Шаги:** выполнить исходный `main.tests.StorefrontTests.test_checkout_applies_active_promo_code`.
- **Фактически:** POST не содержит обязательное поле `agree`, форма должна вернуть ошибки вместо страницы успеха.
- **Ожидается:** тест передаёт согласие и проверяет реальный успешный путь.
- **Связь:** ФТ-11, ФТ-13; исправляется тестами лабораторной 2 без изменения бизнес-логики.

## ДЕФ-05 — анонимный POST отзыва приводит к ошибке сервера

- **Серьёзность:** средняя.
- **Шаги:** отправить POST `/reviews/` без авторизации.
- **Фактически:** представление присваивает `AnonymousUser` внешнему ключу `Review.user`, что приводит к HTTP 500.
- **Ожидается:** отказ с перенаправлением на вход или ответом 403 без необработанного исключения.
- **Проверка:** POST `/reviews/` анонимным клиентом.

## ДЕФ-06 — статистика падает при наличии товара с категорией

- **Серьёзность:** средняя.
- **Шаги:** открыть статистику сотрудником при наличии товара в категории.
- **Фактически:** представление читает `category.title`, отсутствующее поле модели `Category`; HTTP 500.
- **Ожидается:** статистика отображается и для товаров, привязанных к категории.
- **Проверка:** открыть `/stats/` сотрудником при наличии товара в категории.
